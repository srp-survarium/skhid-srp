SURVARIUM 0.26g - LINUX

Install Bash, curl, Winetricks (with cabextract), and Wine 11.0+ with modern
WoW64 support.
Tested: Wine 11.8 Staging WoW64. Use wine and wineserver from the same
installation. A Vulkan-capable graphics driver is required for DXVK.

If the script asks for ntsync, run sudo modprobe ntsync, then try again.
To load it automatically at boot:

    echo ntsync | sudo tee /etc/modules-load.d/ntsync.conf

START

Unpack the Skhid archive into an empty folder with about 10 GB free, then run:

    bash Skhid.sh launcher

The launcher downloads the game and updates; press PLAY when ready.
For an existing game, apply the complete archive over its folder.
To play directly without checking for updates, run bash Skhid.sh, or run
bash play_skhid.sh from game/binaries/x86.

First launch creates a Wine prefix and installs DXVK, Wine Gecko and the font
Calibri (a 27 MB download, which the game's text needs) silently. Later
launches reuse them. Settings: ~/.config/skhid/user.cfg (or
$XDG_CONFIG_HOME/skhid/user.cfg).
Select an English keyboard layout before starting to avoid text-input issues.
For VPN setup, see VPN.txt; split tunnelling must cover Wine.

NVIDIA DLSS (Settings, Graphics, Vulkan options) needs an NVIDIA RTX card and
NVIDIA's driver 470 or later with its Wine files (nvidia/wine/_nvngx.dll under
/usr/lib, /usr/lib64 or /usr/lib/x86_64-linux-gnu; the driver package installs
them). Nothing else to set up. If the option stays grey, the reason is in
game/binaries/x86/srp_patches.log and dlss/dlss_helper.log.

IF IT FAILS

The script refuses old Wine versions and non-modern-WoW64 setups. If switching
from older Wine or seeing a white launcher panel, close both, then rename
game/binaries/x86/wineprefix to an unused backup name and launch again.
Settings stored outside the prefix survive its recreation.

For a memory error, check Wine and the prefix first; do not lower the memory
budgets in the script. Report skhid-wine.log and, for update failures,
updater_skhid.log from game/binaries/x86.

For a crash a developer asked to investigate, start with full-memory dumps:

    SKHID_CRASH_DUMP=full bash Skhid.sh launcher

At the end it lists the crash files (a .dmp of 1-3 GB and its .txt report).

# The number decals (pack number-decals)

The owner, 2026-11-26: "we will add them to the game and I will give a number based on the id for
every single person (in first 1k)". 1,000 decals, Number 1 to Number 1000, from the owner's own
pictures (white typewriter-stencil digits), each given to the account whose id is that number.
Made by `scripts/number-decals/`; the pack is `number-decals@1` of `release/content.tsv`.

## The items

| | |
|---|---|
| dictionary ids | **5001-6000**, Number N is 5000 + N: a free contiguous block (main ends at 3184; the open branches use 4000-4639 and 4800-4801) |
| names | `decals_num_0001` .. `decals_num_1000`; config `gameplay/items/upgrades/decals/char_decal_num_<NNNN>.options`, texture `character/human/decal/num_<NNNN>`, name key `st_character_decals_num_<NNNN>_name` (zero-padded: the keys sort as the numbers) |
| modification ids | 210001-211000 (210000 + N; decals use 200101-200799, camouflages 130000-130400) |
| config | 0.26g's flag `char_decal_4_41` (`prm_decl`, level 4, drop weight 0), its modification id, texture, name key and icon cell changed, as Snufkin's |
| price | none: `base_cost` 0, premium, and `<name>/not_sold` in `content-edit/shop.tsv` (as Snufkin's and Bottled fumo's) |
| icon | one for all, a "№" in the stencil's white at [1, 25] of the decal atlas (the owner, 2026-11-26: one shared icon, the number in the name) |

- **Given only.** No shop sells them (premium, not sold), no drop table has them (drop weight 0),
  a roulette deals no decals, a drop card draws from the drop tables. A player gets his by the
  grant below, or by `release/moderate give`.
- **Names**, generated by `names.py` (never by hand) into the twelve dictionaries: English
  "Number 42", Russian and Ukrainian "Номер 42", Belarusian "Нумар 42", German "Nummer 42", Polish
  "Numer 42", Czech "Číslo 42", Serbian and Croatian "Broj 42", Finnish "Numero 42", Portuguese
  "Número 42", Hungarian "42-es szám" (the -s ending of the last word read out: 3-as, 5-ös, 6-os,
  20-as, 100-as, 1000-es). The pack's own `localization_add` carries its six languages from them,
  as fumo-neco-decals does.

## The textures

- **Diffuse**: DXT5 256x256, 7 mips (the owner, 2026-11-26: 256², not the flags' 512², for the
  size below). White everywhere, the alpha the picture's. Every number cut by one window: the rows
  of all 1,000 pictures (one baseline) and the widest number's width ("1000", 1,200 px) fitted in
  the texture with 8 px each side, so every number has the same size; each number's own middle in
  the middle across. "1000" spans the decal's width, its digits are about a quarter of its height
  (3.7 cm at the editor's starting 15 cm, 10 cm at the largest, 40 cm).
- **Normal map and specular**: 16x16, 3 mips (DXT5, DXT1), one value each: 4_41's cloth weave's
  median and its cloth's specular. 0.26g's fresnel maps are 16x16 already, and the bake samples
  each layer on its own (0.69d's Boar hunter has a 128² normal map with a 512² diffuse). The
  fresnel map and the four `.options` are 4_41's.
- **Sources**: the owner's 1,000 PNGs (1920x1080, 25 MB, with Photoshop's broken XMP) are not
  committed; `sources.tsv` holds their sha256 and the builder reads only their pixels. They are
  kept in `private/number-decals/` of the main checkout. The icon (`icon.png`, 4 KB) is committed:
  `make_icon.py` drew it once from GNU FreeFont's FreeMono Bold "№" (the pictures have no such
  sign), its edge roughened like the digits'.

## Size and the client's limits

| | |
|---|---|
| the pack | 9,000 files, 91.4 MB: 1,000 diffuse textures of 87.5 KB (87.5 MB), the rest 4 KB a number |
| at the stock flag's sizes | 877 KB a number, 877 MB: why the diffuse is 256² and the normal map and specular 16² |
| `resources.db` | stores files as they are (no compression): about +91 MB on players' disks and in the patch |
| the dictionary | 1,000 rows more in `items_dict` (about 4,000 items in all) |
| the localization | 1,000 keys more in each of the twelve (3,054 to 4,054 keys) |
| the decal atlas | one cell ([1, 25]); per-number icons were not possible: the atlas is 5 rows of 82 px and the porter widens it only by columns, 1,000 cells would be about 19,800 px wide (Flash's bitmaps stop at 8,191, D3D11's textures at 16,384), and the lobby cuts every cell into its own bitmap at its start (27 MB more in Scaleform's heap of the 32-bit game) |

- Textures are read when a bake asks for them: a player's game loads the decals it shows, not
  the 1,000. The item configs (1.4 KB each) and the dictionary rows are read at the game's start.
- Nothing here is near a limit the code shows: dictionary ids are u16, decal slots are per item
  (two on a vest or trousers, one on a weapon), and an account gets one decal.

## The grant

The account of id N, 1 to 1000, gets Number N (**number = account id**, the coordinator's and the
owner's choice of 2026-11-26: the id players see on the site). Ids no account has give nothing
(ids 1-3 and 5 have none; the 2026-11-22 copy has 904 accounts, ids 4 to 908). Bans do not
matter. The test account (4) and System (590, the server notices' name) get none.

- **At the release** that ships the pack: `scripts/number-decals/grant.py`, a one-off script as
  the release skill's step 4 has it (not srp's start). Without `--apply` a dry run: one row an
  account (number, id, 0.26g name, what it does) and the totals. With `--apply`, srp stopped: a
  copy to `backups/srp-<unix>-before-number-decals.db` first, then one transaction: each decal into
  its account's inventory (its next item id, after its items, full condition) and the mark
  `number_decals_given` in `g26_meta`. Run again it gives nothing (the mark), and an account that
  owns its decal already is left alone. It reads `accounts.id` and the 0.26g tables, nothing of the
  nickname index.
- **Later**: an account of such an id with no 0.26g account yet (7 on 2026-11-22) gets its number
  when srp makes that account (`session` `v026g::number_decals::give_new`, from `sign_up`), if
  the game data has the decal. The same two accounts are left out.
- The dry run of the 2026-11-22 copy: 895 decals to give, 7 at a later sign-up, 2 left out, 96
  numbers no account had yet (ids 909-1000 came later).
